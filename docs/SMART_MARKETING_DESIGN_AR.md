## الهدف والنطاق

إضافة «مدير التسويق» إلى أدوات المكتب الحالية. يروّج لاسم المكتب وخدماته ورابطه، ويجهز تصاميم ونصوصًا وحملات وفرص ظهور وتقارير فعلية. لا يقرأ عقارات العملاء أو محادثاتهم أو تفاصيل صفقاتهم لتوليد المحتوى. الإنتاج خارج نطاق المهمة؛ التنفيذ والنشر والاختبار على Staging فقط.

مسار الوسيط: فتح الأداة، رؤية اقتراح، تجهيز إعلان، معاينته وتعديله، اعتماده، مشاركته، متابعة النتائج. تبقى الأقسام الخمسة داخل الأداة نفسها؛ الخطة الأسبوعية ضمن اقتراحات الحملات والإعدادات داخل الأداة.

## العزل والأذونات

يكون مصدر الهوية ملف المكتب الموثوق في الخادم. كل سجل تحت `offices/{officeId}`، وكل إجراء يتحقق من Firebase ID token وعضوية المكتب الحالية. لا يُقبل `officeId` أو الشعار أو الهاتف القادم من الطلب باعتباره إثبات ملكية أو هوية.

يقرأ عضو المكتب المحتوى الخاص بمكتبه. الإدارة والاعتماد والإعدادات تخص دور الإدارة الحالي. إنشاء المسودات يتبع صلاحيات الأعضاء الحالية. تعتمد هذه الخدمة أذونات النظام القائمة، دون توسيع دور مستخدم موجود. مفاتيح المزودين في الخادم فقط. الطلبات غير الموثقة والمكتب الآخر والعضوية الملغاة مرفوضة حتى عند تعديل عنوان URL أو جسم الطلب.

لا يمرر محول الذكاء الاصطناعي سوى اسم المكتب، خدماته العامة، مدينته، الجمهور والميزانية والإحصاءات المجمعة المصرح بها. لا تُرسل بيانات العملاء. يُسجل الاعتماد بمعرف المستخدم والوقت وإصدار المحتوى، ويصبح أي تعديل لاحق مسودة تتطلب اعتمادًا جديدًا.

## السجلات والعقود

- إعدادات: `marketingSettings/current`، المنطقة والجمهور والميزانية والقنوات العامة وتفضيلات الخط، مع تحقق وحدود أطوال وحجم الطلب.
- مسودات: `marketingDrafts/{id}`، النصوص، القالب، أبعاد التصدير، مواقع النصوص، إصدار الهوية، حالة المسودة أو الاعتماد، منشئها وأوقاتها.
- حملات: `marketingCampaigns/{id}`، الهدف والقناة والميزانية المقترحة ورابط التتبع وسبب الاقتراح. الاعتماد لا يعني النشر.
- فرص: `marketingOpportunities/{id}`، URL، المصدر، وقت اكتشافه والتحقق منه، شروط النشر ومصدرها، المفضلة والحالة.
- تدقيق: `marketingAudit/{id}`، الأحداث المؤكدة فقط. لا تُسجل رسالة «تم النشر» عند فتح تطبيق المشاركة.
- قياس: سجل أحداث محدود وإحصاءات يومية؛ معرفات فريدة تمنع إعادة احتساب التحويل الناجح.

مسارات داخلية مقترحة تحت `/office/marketing/`: الحالة والإعدادات، المسودات والاعتماد، الاقتراحات، البحث والفرص، والتقارير. تستخدم عقود الأخطاء وطريقة الاستدعاء الحالية. لا يُسمح بإرسال URL مزود أو تعليمات نظام من الواجهة.

## الاستوديو العربي والتصدير

قوالب تعمل محليًا دون خدمة صور: التعريف بالمكتب، إضافة العقار، إرسال الطلب، الخدمات، الرابط، التواصل، النص الحر. مقاسات 1080×1080 و1080×1920، مع مقاس بنر محدد عند إنشاء التصميم. بيانات التواصل العامة المفقودة لا تُستبدل بقيم تخمينية.

الرسم Canvas باستخدام تشكيل المتصفح للعربية، واتجاه RTL، وانتظار `document.fonts.ready` وتحميل الخط المختار قبل المعاينة والتصدير. يعتمد الاستوديو خط الواجهة الحالي وخيار نسخ/كوفي محليًا إن توفر خط مرخص. لا تُرسم الحروف منفردة ولا تُعكس السلاسل العربية يدويًا.

تستخدم المعاينة والتصدير دالة الرسم نفسها، والشعار بوضع contain دون قص. تلتف الأسطر حسب قياس الخط الفعلي. يحافظ الرابط على ترتيب LTR داخل منطقة مستقلة. تعديل الحجم والموضع ضمن مساحة آمنة وبحقول مناسبة للجوال. فشل تحميل شعار أو خط مطلوب يظهر خطأ قابلًا للإصلاح، ولا يُنتج إعلانًا ناقصًا بصمت.

يصدر `canvas.toBlob` ملف PNG فعليًا بالأبعاد المختارة. يُعالج CORS للشعار من مسار الوسائط المصرح به؛ لا يُبنى proxy مفتوح. تنزيل الصورة لا يتطلب مزود توليد صور. توليد الخلفية بالذكاء الاصطناعي خيار مستقل عند وجود خدمة مهيأة، مع إبقاء النص العربي والشعار فوقها بالرسم المحلي.

## الاقتراحات والنصوص والخطة

قواعد محلية معلنة تنتج أفكارًا أولية بناء على خدمات المكتب ومدينته والجمهور والميزانية. يُعرض أنها اقتراحات مبنية على بيانات المكتب، دون ادعاء استخدام ذكاء اصطناعي إن لم يحدث استدعاء فعلي. محول الذكاء الاصطناعي اختياري لتحسين التخصيص، مع مهلة وحدود استهلاك وتخزين بحسب نسخة بيانات الإدخال.

كل حملة لها هدف وجمهور وقناة وفكرة وسبب وميزانية اختيارية قابلة للتعديل؛ لا تظهر توقعات تحويلات مضمونة. تنتج النصوص نسخة قصيرة ومتوسطة ودعوة إجراء لكل قناة والرابط الحقيقي. خطة الأسبوع تستخدم توقيت الرياض؛ أوقات النشر فرضيات اختبار إلى أن تتوفر نتائج فعلية.

## البحث الحقيقي والتحقق

خدمة بحث مستقلة قابلة للتهيئة في الخادم. عند غيابها تظهر «يتطلب ربط خدمة البحث». لا يُستبدل البحث بقائمة نتائج نموذجية. الروابط الرسمية الثابتة، إن عرضت، تُسمى إرشادات عامة وليست فرصًا مكتشفة.

كل فرصة تتضمن مصدرًا وتاريخًا. المجانية والتكلفة وشروط النشر تُعرض «غير معروفة» إذا لم يدعمها المصدر. صلاحية الرابط منفصلة عن إذن الإعلان داخله. لا يقرأ النظام مجموعات خاصة ولا يدّعي معرفة سياسة نشر غير معلنة.

فحص الروابط يحظر المخططات غير HTTP/HTTPS، وlocalhost والعناوين الخاصة وخدمات metadata، ويتحقق من كل تحويل مع حد للتحويلات والحجم والمهلة. يمنع استغلال التحقق للولوج إلى الشبكات الداخلية. لا تُنفذ تعليمات المواقع المسترجعة ولا يسمح لها بتغيير قواعد النظام أو اتخاذ إجراء نشر.

## المشاركة والقياس

المشاركة اليدوية تستخدم Web Share عند دعم مشاركة الملفات، أو تنزيل PNG ونسخ النص وفتح رابط مشاركة رسمي. تيليجرام وواتساب لا يضمنان إرفاق PNG عبر رابط نصي؛ يُشرح الإجراء الفعلي. لا يُغيَّر تكامل قنوات المكتب الحالي.

UTM تُضاف إلى نسخة المشاركة فقط مع إبقاء رابط المكتب الثابت محفوظًا. يلزم اختبار وضعها قبل Hash وأن وصولها ينجو من الانتقال إلى نماذج الإدخال. لا يساوي النقر زيارة مكتملة ولا يساوي فتح النموذج تحويلًا. يسجل العرض أو الطلب كتحويل بعد نجاح الحفظ في الخادم فقط، مرة واحدة لمعرف السجل والحملة. ترتبط التقارير بسجلات القياس فقط ولا تقرأ تفاصيل العملاء.

تظهر فترة القياس ووقت بدايته وحدوده. عدم وجود أداة قياس مفعّلة يُعرض «غير متاح»؛ بدء قياس جديد بلا أحداث يعرض صفرًا. تطبق موافقة التتبع عند انطباقها، مع أقل بيانات ممكنة ومدة احتفاظ محددة في إعدادات الخادم. لا يحفظ IP خامًا في التقارير التسويقية.

## الفهرسة

يُفحص مسار المكتب العام وخدمة المعاينة الموجودة قبل أي تعديل. البيانات المطلوبة عنوان ووصف وOG وcanonical للرابط الصحيح. تغيير metadata بعد JavaScript وحده لا يُعتبر إثباتًا لنجاح الفهرسة. يُفحص HTML الأولي وrobots وسلوك مسار المشاركة. إن تطلب الحل إعادة هيكلة المسارات، يُوثق القيد دون كسر روابط Hash أو وعد بترتيب مضمون.

## مراحل التنفيذ والقبول

1. إضافة الأداة والإعدادات والعقود والعزل. اختبار عضو ومدير ومكتب آخر وإلغاء العضوية.
2. الاستوديو والنصوص وحفظ المسودات. PNG لكل مقاس وخط، وشعار محفوظ النسبة، ونص طويل ومختلط عربي/لاتيني، وهاتف ورابط صحيحان.
3. الاقتراحات والبحث. اختبار حالات مزود متصل وغير مهيأ وفشل/مهلة، ومصادر وروابط موثقة، ومنع SSRF.
4. الاعتماد والمشاركة والقياس. إلغاء المشاركة لا يسجل نشرًا؛ تكرار التحويل لا يزيد العدد؛ تبديل المكتب ينظف الشاشة والحالة.
5. بيانات المشاركة والفهرسة. لا تتغير روابط عامة منشورة؛ اختبارات regres­sion لمسار المكتب والمعاينة.
6. اختبار مكتبين معزولين والجوال، والرحلة العقارية الحالية، ثم نشر Staging والتحقق من Worker وFirebase project والواجهة الحية.

يستخدم node:test لقواعد المجال وعقود الخدمة، واختبارات Firestore Rules للعزل، وPlaywright للرحلة والتصدير العربي على 360 و390 و430 بكسل. يحتاج التصدير فحصًا بصريًا فعليًا إضافة إلى اختبار نوع PNG وأبعاده. يُسجل لكل اختبار ما إذا كان محليًا بمحول وهمي أو اتصالًا حيًا؛ الأول لا يثبت جاهزية API الخارجي.

## شروط التسليم

PR إلى فرع Staging المناسب دون دمج تلقائي. رابط النسخة التجريبية وصورة الشاشة وعينة PNG محفوظة ونتائج الاختبارات وقائمة الملفات. مثال فرصة فقط عند وجود بحث حقيقي ناجح. تُعرض الخدمات غير المهيأة بوضوح. لا يُعلن اكتمال الميزة قبل تحقق القبول الحي؛ هذه الوثيقة ليست دليل تنفيذ.
