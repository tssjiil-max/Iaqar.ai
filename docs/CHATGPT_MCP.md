# ربط ChatGPT بمكتبك (خادم MCP — قراءة فقط)

**الحالة:** جاهز تقنيًا على Staging. **لم يُجرَّب من حساب ChatGPT فعلي بعد** — هذا لا يُعتبر «متصلًا» حتى ينجح الاتصال من حسابك.

## ما يفعله
خادم MCP عند `POST /mcp` يقدّم أدوات قراءة فقط فوق خدمات المكتب الموجودة (باحث الفرص، السجلات). لا محرك بحث ولا مطابقة جديد.

| الأداة | الوظيفة |
|---|---|
| `office_overview` | ملخص المكتب (عروض/طلبات مفتوحة، فرص جديدة) |
| `list_finds` | أقوى الفرص الخارجية مع الأسباب ورابط المصدر |
| `get_find` | تفاصيل فرصة (دون بيانات تواصل) |
| `search_records` | البحث في عروض وطلبات المكتب |
| `scout_status` | حالة المصادر والبحث الجاري |

كل الأدوات `readOnlyHint`. لا أداة تكتب أو ترسل واتساب أو تتواصل مع أحد.

## الأمان
- مفتاح بنطاق `mcp:read` خاص بمكتب واحد، يُنشأ لمدير المكتب فقط (`/os/mcp/key/create`)، يظهر مرة واحدة، يُخزَّن مُجزَّأً، ويُلغى فورًا (`/os/scout/ingest/key/revoke`).
- المكتب يُؤخذ من المفتاح لا من الطلب. مفتاح الاستقبال لا يفتح MCP والعكس.
- أرقام الهواتف تُحجب من كل المخرجات، حتى لو وردت في نص الإعلان.
- حد 300 استدعاء/ساعة للمفتاح، وكل استدعاء يُسجَّل (اسم الأداة فقط، بلا محتوى).
- يعمل فقط حيث `MCP_SERVER = "enabled"` (Staging والمعاينة). **غير موجود في Production.**

## قيد معروف: المصادقة
ChatGPT يطلب OAuth أو «بلا مصادقة». هذه النسخة **لا تنفذ OAuth**؛ تستخدم مفتاحًا سريًا في الرابط `https://<worker>/mcp/<المفتاح>` مع «بلا مصادقة». هذا أضعف من OAuth لأن الرابط يُخزَّن في ChatGPT، ويخفف ذلك: قراءة فقط، بلا هواتف، مفتاح قابل للإلغاء. OAuth مرحلة لاحقة قبل أي أداة كتابة.

## خطوات المالك (اشتراك Plus)
1. من إعدادات المكتب أنشئ مفتاح MCP (يظهر مرة واحدة).
2. ChatGPT ← Settings ← Apps & Connectors ← Advanced ← Developer mode.
3. Create ← الاسم «مكتبي» ← الرابط أعلاه ← Authentication: No authentication ← Create.
4. في محادثة جديدة اختر التطبيق واسأل: «اعرض ملخص مكتبي».
(الخطوات من مصادر طرف ثالث وقد تختلف الواجهة؛ خطة Plus قد تقتصر على القراءة وهو المطلوب هنا.)
