# Public iAqar product tour (Staging only)

Purpose: help a Saudi broker understand the real office journey before registration, in a short visual tour. `/tour` is public and read-only. Bare `/` opens it; all query/hash links and office paths retain their existing routing. The existing approval form is linked at `/?tour=1#/register`.

Evidence baseline: Staging fc68af7 (public version checked), Production dbb69b3 (public version checked). On the shared line, intake → reviewed record → candidate match → broker decision → negotiation, proposals/viewing → agreement/follow-up. Match comparison, room parts and SVGs are reused from current pure display modules; no live office store is imported.

External cooperating broker is implemented, but cooperation requires VERIFIED representation and ACCEPTED cooperation. Telegram and WhatsApp configuration exists, but no claim of fully active channels for each office is made.

Marketing is on separate branch `codex/smart-marketing-staging-20261010`, commit 775ac67f91cf78916cf56120ed206f83e008a3e3. It is not in the shared Staging/Production line. The tour labels it an independent experimental preview. Capabilities verified in its source: office campaigns, channel suggestions, ad copy, actual PNG renderer, persisted drafts/approval, manual sharing. Acquisition metrics are unavailable; search/generative providers require configuration. No automatic publishing or property-specific ad tool is promised.

Marketing example is generated by the existing renderer at that SHA, using only fictional office name, no phone, and reserved `example.invalid/demo`. `marketing-demo.png` is the source output, WebP is the compressed display copy. `REGENERATE_MARKETING=1 node scripts/qa/public-tour.e2e.mjs` regenerates it and verifies layouts at 320, 390, 768, 1440px.

Analytics: reuses the measurement ID configured on the Firebase Staging project. Explicit opt-in, respects DNT/GPC, no name/phone/email/office/account IDs are sent. The allowlist includes tour_visit, watch_click, section_view, marketing_view, demo_step, trial_click, registration_start and registration_complete. Registration complete means successful submission of the existing broker approval application, not office activation. GA runs only in an opaque sandbox iframe with an empty document, sanitized page location/referrer, denied cookie/advertising storage and no persistent identifier. Automatic measurements cannot inspect registration or office DOM. The iframe is removed on consent withdrawal, login or office entry. Metrics failure is non-blocking. Denied consent loads no external scripts. Production measurement is disabled.

Deployment: dedicated Hosting-only job on the new branch, with a current-Staging-SHA lease. Uses existing staging credentials and channel, no Worker deployment or Firestore changes. Refuses if Staging has advanced. Production version is checked before and after. Preserve this branch in the unified Staging line before subsequent regular Staging releases, otherwise the next baseline release can replace the tour.
