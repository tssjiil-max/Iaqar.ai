## الخلل المثبت

كان تعبير إزالة المسافات في `parseIntakeAmount` مكتوبًا بشرطات هروب مكررة داخل تعبير نمطي حرفي. لذلك كان يزيل الأصفار وحروفًا مثل `s` و`u` و`a` بدل الاقتصار على المسافات.

- `600000` تحول إلى **6**.
- `٦٠٠٬٠٠٠٫٥٠` رُفض رغم صحته، في Node وفي النموذج الحقيقي داخل المتصفح.
- `٦٠٠٠٠٠٫٥٠٥` تحول إلى **6.55** بدل رفض أكثر من منزلتين عشريتين.

التصحيح البرمجي سطر واحد لإزالة المسافات فقط. أضيف اختبار انحدار للأصفار والمسافات والحروف والشرطة العكسية، وأُثبت فشله قبل التصحيح ثم نجاحه بعده.

`600000.5` مساوية عدديًا لـ`600000.50`؛ Firestore لا يحتفظ بصفر تنسيق زائد في نهاية العدد. اختُبرت القيمة العددية ونوع العملية، وليس مظهر تنسيق العملة.

- المتصفح: Chromium 140.0.7339.16 عبر Playwright، إعداد جوال 390×844 واللغة ar-SA.
- استُخدم `access-gate.js` الأصلي مع وحدات الإدخال الأصلية وFirebase Browser SDK الحقيقي. جرى النقر والتعبئة والإرسال في DOM فعلي.
- استُخدم غلاف HTML اختباري بسيط لعزل وحدة الإدخال عن بقية التطبيق. هذا اختبار تكامل للنموذج والحفظ، وليس اختبارًا شاملًا لكل الموقع أو تسجيل الدخول.
- الكتابة من SDK خضعت لملف `firestore.rules` الموجود بالمستودع دون تغيير.
- أُعيدت قراءة كل مستند بواسطة HTTP GET مستقل من المحاكي؛ لا اعتماد على ذاكرة SDK المحلية. القراءة الإدارية التجريبية محلية فقط؛ صلاحيات قراءة المستخدم النهائي ليست ضمن هذا الاختبار.

npm run check
