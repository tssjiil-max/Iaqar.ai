## الحالة وحدود التسليم

تنفيذ خلفي حقيقي داخل Cloudflare Worker الحالي. ليس نقلًا إلى Vercel، ولا CRM أو محرك مطابقة آخر. التشغيل الافتراضي متوقف؛ المفاتيح والتصاريح الحية غير مكتملة. لا تغيير في Production أو Meta أو تسجيل الرقم، ولا رسائل فعلية أُرسلت أثناء التنفيذ.

المصدر: `codex/unified-staging-lineage-2026-08-29` عند `d94c6a586c82147d31921eb00636090af0b5f6e3`. ملف `version.json` المنشور أعاد نفس SHA ووقت `2026-10-16T18:37:44.700Z`.

فحص Cloudflare للقراءة فقط، لقائمة **أسماء** الأسرار في `iaqar-intake-staging`، أثبت وجود `META_APP_SECRET` و`META_WEBHOOK_VERIFY_TOKEN`، وغياب `ANTHROPIC_API_KEY` و`META_WHATSAPP_ACCESS_TOKEN`. لم تُقرأ قيم أسرار. نتيجة Vercel للمستودع المحدد لم تُرجع مشاريع ضمن النطاق المتاح؛ المستودع يستخدم Firebase Hosting وCloudflare Worker، لذلك لم تُنشأ نقطة استقبال موازية في Vercel.

تم فحص طلبات الدمج المفتوحة؛ PR #235 لتوحيد الواجهات بقي دون تعديل أو دمج. هذه الدفعة لا تعدل الواجهات أو نظام التصميم.

## ما كان موجودًا وما أُكمل

| الجزء | الموجود | التغيير |
|---|---|---|
| GET `/meta/webhook` | Verify Token ومقارنة آمنة | أُبقي واستُخدم واختُبر |
| POST `/meta/webhook` | HMAC، ربط الرقم بالمكتب، Inbox، استقبال تقليدي | حدود حجم، انتظار أخطاء التحقق، تفريع تجريبي لكل مكتب دون فقد رسائل بقية المكاتب |
| الحفظ | Firestore وcreate-only | إصلاح عدم تصنيف 400/404 كرسائل مكررة؛ فشل التخزين يعيد خطأ لتعيد Meta المحاولة |
| المعالجة | معالجة تقليدية داخل طلب الاستقبال | طابور دائم مستقل عن عمر الطلب، بمؤشرات إلى Inbox الموجود |
| Claude | غير مربوط بهذا المسار | Messages API عبر محول خادم ثابت، مهلة، JSON مقيد، تصنيف النية والتصعيد |
| العقل المركزي | guestSearch ومحرك المطابقة المركزي | إعادة استخدامه بعد موافقة العميل، دون مخزون أو محرك آخر |
| العملاء | `offices/{office}/contacts` | إنشاء contact عند غيابه فقط، دون الكتابة فوق اسم أو بيانات مؤكدة |
| الرد | إرسال Cloud API غير مكتمل | محول نصوص مع نافذة خدمة وضوابط مكتب ومستلم وتعايش، وحفظ معرف الرسالة |
| الحالات | لم تكن معالجة في هذا المسار | callback آمن يربط sent/delivered/read/failed بالسجل الصحيح دون تخفيض الحالة |
| التحكم | صلاحيات Office OS | status/settings/run لمدير المكتب، وإيقاف دون فصل الرقم |

## رحلة التنفيذ

1. GET يتحقق من Verify Token، وPOST يتحقق من HMAC على الجسم الأصلي قبل قراءة بيانات المكتب.
2. الأحداث الموقعة فقط تدخل المسار. حد الجسم 1 MiB يُطبق أثناء القراءة. رسائل الصدى والأنواع غير المعروفة لا تستدعي Claude.
3. الأرقام المشمولة في قائمة المكاتب التجريبية تدخل الطابور؛ غير المشمولة تستمر في الاستقبال السابق. WABA والرقم والمكتب متطابقة.
4. يُحفظ أصل الرسالة في Inbox بـcreate-only، ثم مؤشر عمل دائم. إعادة الحدث تصلح الحفظ الجزئي ولا تكرر الرسالة.
5. `waitUntil` يبدأ محاولة سريعة بعد الحفظ؛ Cron الموجود كل خمس دقائق يعيد التقاط العمل المتبقي. الاعتمادية على الحفظ الدائم وليست على بقاء الطلب مفتوحًا.
6. قفل محادثة بـlease وCAS وقائمة pending يحافظ على تسلسل الرسائل. الحد 100 رسالة معلقة لكل محادثة؛ عند تجاوزه يعاد 503 ولا تُقرّ رسالة غير محفوظة في الطابور.
7. Claude يصنف النية والتصعيد فقط. لا يختار عنوان API أو مستلمًا أو أداة، ولا ينشئ عقارًا أو سعرًا أو نص اتفاق. الردود تُبنى من قواعد المكتب والبيانات الحقيقية؛ لا ادعاء بوجود موظف تفاوض مستقل.
8. استخراج تفاصيل الطلب يستعمل قواعد المحادثة العربية الموجودة. يُطلب الناقص تدريجيًا، ثم موافقة صريحة على الحفظ والبحث والتواصل. البحث يستعمل guestSearch والعقل المركزي والمخزون المنشور فقط؛ أقصى ما يرسل ثلاث نتائج، بلا بيانات المالك الخاصة.
9. قبل الإرسال يعاد التحقق من الملكية والمكتب والقفل والإيقاف والمستلم ونافذة 24 ساعة. نتائج البحث تُعاد قراءتها بعد أي Retry فلا تُرسل نسخة قديمة من عرض أُلغي أو تغير سعره.
10. STOP وطلب التدخل البشري يسجلان أثناء الاستقبال، حتى يوقفا ردًا سابقًا ما زال تحت المعالجة. تغيير السعر والعقود والعمولة والبيانات الحساسة يذهب للمراجعة البشرية.

## التخزين والصلاحيات

- أصل الرسائل والنتيجة والمحاولات والحالة: `offices/{officeId}/inbox/{wa_hash}`.
- سياق القناة فقط: `offices/{officeId}/whatsappConversations/{hash}`. هذه ليست قاعدة عملاء موازية؛ لا تُنشأ قوائم عقارات فيها.
- مؤشرات العمل: `serviceQueues/whatsapp/jobs/{officeId_inboxId}`. لا تحتوي على نصوص العملاء أو أسرار. مؤشر العمل يُحذف عند اكتماله؛ أصل الرسالة يبقى في Inbox.
- `DEAD_LETTER` و`DELIVERY_UNKNOWN` وحالات التدخل البشري تبقى في Inbox ولا يعاد إرسالها آليًا.
- ميزانية 200 محاولة Claude للمكتب في اليوم محفوظة بـCAS في usage؛ عدادات الرموز من استجابة المزود. قيمة الفاتورة المالية غير محسوبة ولا تُختلق.
- قوائم المحادثات والطابور تقع ضمن المنع الافتراضي لقواعد Firestore الحالية؛ الوصول من Worker فقط. لم تتغير قواعد Firestore ولم يُدّع اختبار Emulator جديد.
- سياسة الاحتفاظ الآلية الجديدة/TTL لم تُفعّل. يلزم تحديد مدة مع المالك قبل Production؛ لا يوجد حذف تلقائي لبيانات العملاء في هذه الدفعة.

## Retry ومشكلة نتيجة الإرسال غير المؤكدة

خمس محاولات كحد أقصى، بانتظار 30 و60 و120 و240 ثانية حتى سقف 30 دقيقة. أخطاء Claude تحفظ الرسالة، وأخطاء المصادقة تحول للبشر. HTTP 429 الصريح يعيد محاولة الرد المحفوظ دون استدعاء Claude مرتين. عدم وضوح قبول Meta للرسالة، مثل انقطاع الشبكة بعد إرسال الطلب، يؤدي إلى DELIVERY_UNKNOWN ولا يعاد الإرسال آليًا. لا يوجد وعد تقني بإرسال خارجي exactly-once؛ هذا الحد مقصود لمنع تكرار الرسائل عند الغموض.

الإيقاف يوقف المحاولات التالية دون تغيير WABA أو الرقم. الرسائل الواصلة أثناء توقف المكتب تُحفظ كـAUTOMATION_PAUSED للمراجعة؛ إعادة التفعيل تسمح بالرسائل الجديدة ولا تتجاوز إلغاء اشتراك العميل.

## إعدادات التفعيل التجريبي

كل هذه القيم **على Worker التجريبي فقط**. لا تُرسل قيم الأسرار في المحادثة ولا توضع في الكود:

| المتغير | الغرض |
|---|---|
| `ANTHROPIC_API_KEY` | مفتاح Claude API — غير موجود عند الفحص |
| `ANTHROPIC_MODEL` | اسم نموذج مصرح ومدفوع في حساب المالك؛ لا يُفترض نموذج افتراضي |
| `META_WHATSAPP_ACCESS_TOKEN` | Token رسمي مخول للرقم — غير موجود عند الفحص |
| `META_APP_SECRET` | التحقق من توقيع Meta — موجود الاسم |
| `META_WEBHOOK_VERIFY_TOKEN` | تحقق GET — موجود الاسم |
| `WHATSAPP_AGENT_ENABLED=enabled` | تفعيل المعالج التجريبي؛ الغياب يعني متوقفًا |
| `WHATSAPP_AGENT_OFFICE_IDS` | قائمة officeId مصرح بها، مفصولة بفواصل |
| `WHATSAPP_AGENT_ALLOWED_RECIPIENTS` | أرقام اختبار مصرح بها بصيغة دولية، مفصولة بفواصل |
| `WHATSAPP_AGENT_SEND=enabled` | السماح بطلب إرسال فعلي؛ بدونه تحفظ محاكاة SIMULATED |

بالإضافة إلى ذلك: `autoReplyEnabled=true` على تكامل المكتب، وربط رقم حالي `status=connected`, `isOnBizApp=true`, `platformType=CLOUD_API`, `metaPhoneStatus=CONNECTED`. هذه حقول محفوظة وليست إثباتًا لاختبار حي حديث. يلزم فحص Meta الفعلي واستمرار تطبيق الجوال قبل التفعيل.

النقطة الحالية: `https://iaqar-intake-staging.iaqar-ai.workers.dev/meta/webhook`. لا تسجيل تقليدي أو register/deregister أو نقل رقم في الكود الجديد. اسمح باشتراك messages الذي يحمل الرسائل وحالاتها؛ أصداء تطبيق الجوال لا تُعامل كرسائل عملاء.

لا يعتمد التشغيل على اشتراك ChatGPT/Claude الاستهلاكي أو جلسة متصفح. تكاليف API بحسب حساب المالك؛ لم تنفذ مكالمات مدفوعة أثناء الاختبار.

## واجهات إدارة التشغيل

كلها POST بهوية Firebase وعضوية مكتب موثقة؛ تُقبل من مدير المكتب فقط:

- `/os/whatsapp-agent/status` مع `{officeId}`: الإعدادات المنقحة وأعداد عينة حتى 300 رسالة. ليس إثباتًا لاتصال حي.
- `/os/whatsapp-agent/settings` مع `{officeId,enabled:false}`: إيقاف فوري للمعالجة المستقبلية، دون فصل الرقم. التشغيل يرفض الإعدادات الناقصة.
- `/os/whatsapp-agent/run` مع `{officeId}`: تشغيل دفعة طابور المكتب للاختبار؛ كل ضوابط الإرسال تطبق من جديد.
