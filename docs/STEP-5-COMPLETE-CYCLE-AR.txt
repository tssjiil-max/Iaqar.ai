دورة التشغيل الكاملة — Workflow V5
===================================

1) الاستقبال
- الرسالة الخاصة تصل من Meta إلى /meta/webhook، أو يشارك الوسيط رسالة قروب يدويًا إلى تطبيق IAQAR عبر Android Share Target.
- يحدد النظام المكتب بواسطة officeId أو Phone Number ID المربوط بالمكتب.
- تحفظ الرسالة داخل inbox ثم تحلل محليًا.

2) التصنيف والاستخراج
- ينشئ النظام طلب عميل أو عرض مالك.
- يستخرج نوع العملية، الحي، نوع العقار، السعر، المساحة، الغرف، الجوال، الجاهزية المالية، الاستعجال، وكون العرض من المالك مباشرة.

3) المطابقة
- يقارن الطلبات والعروض داخل المكتب نفسه فقط.
- يرفض التعارض بين البيع والإيجار، والفروق غير المنطقية في السعر أو الغرف أو الحي والنوع.
- يحفظ نسبة المطابقة، أسبابها، التحذيرات، ترتيب النتيجة، وجاهزية الإغلاق.

4) متابعة المطابقة
- لكل نتيجة مطابقة سجل مستقل وملاحظات ومواعيد متابعة.
- الحالات: نشطة -> بانتظار رد -> موعد معاينة -> تفاوض -> تمت الصفقة أو أُغلقت.
- كل انتقال يسجل داخل timeline ولا يحذف التاريخ السابق.

5) الصفقة
- عند بدء التفاوض تنشأ صفقة مرتبطة بالمطابقة.
- المراحل: التواصل -> المعاينة -> التفاوض -> اتفاقية الوساطة -> جاهزة للإغلاق -> تمت الصفقة.
- يظهر في مساحة العمل مؤشر صحة الصفقة والخطوة التالية وموعد المتابعة.

6) النجاح أو الفشل
- عند إتمام الصفقة تتحول المطابقة الفائزة إلى «تمت الصفقة».
- تغلق بقية مطابقات طلب العميل نفسه تلقائيًا بسبب «تمت الصفقة مع عقار آخر».
- عند فشل صفقة تغلق المطابقة المرتبطة بها فقط، وتبقى البدائل الأخرى نشطة مع تاريخها الكامل.

7) التنبيهات
- Cloudflare Cron يفحص المتابعات المستحقة كل ساعة.
- ينشئ Alert داخل المكتب ويرسل FCM للأجهزة المفعلة.
- الضغط على الإشعار يفتح المطابقة أو الصفقة المقصودة.
